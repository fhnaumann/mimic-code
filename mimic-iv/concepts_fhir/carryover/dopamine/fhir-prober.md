## Resource mapping and discriminator

`mimiciv_icu.inputevents` maps to the ICU `MedicationAdministration` resource
stream. The upstream ICU ETL is
`/Users/nau025/Documents/mimic-fhir/sql/fhir_medication_administration_icu.sql`.
It emits one `MedicationAdministration` per inputevents row, writes the
source `itemid` as a medication `CodeableConcept` coding, and uses the ICU
Encounter as `context`.

The supporting `mimiciv_icu.icustays` table maps to the ICU `Encounter` stream
generated by `/Users/nau025/Documents/mimic-fhir/sql/fhir_encounter_icu.sql`.
That ETL writes `stay_id` as the identifier value under the
`.../identifier/encounter-icu` system. It is a FHIR-side support join for the
source `stay_id`; it is not an additional source SQL relation or output row
generator.

The exact served coding for this source literal is:

```text
system = http://mimic.mit.edu/fhir/mimic/CodeSystem/mimic-medication-icu
code   = "221662"
display = "Dopamine"
```

Use the exact `system + code` pair as the discriminator. Do not use
`meta.profile`; the curated notes state that profile values can collapse in a
merged warehouse variant. The target coding projection can constrain both
parts inside the repeating `forEach`:

```json
{
  "forEach": "medication.ofType(CodeableConcept).coding.where(system='http://mimic.mit.edu/fhir/mimic/CodeSystem/mimic-medication-icu' and code='221662')",
  "column": [
    { "path": "code", "name": "item_code" },
    { "path": "system", "name": "code_system" },
    { "path": "display", "name": "code_display" }
  ]
}
```

The same result is obtained by constraining the `forEach` to the ICU system
and applying `item_code = '221662'` in SQL. The code is a string on the FHIR
side; no terminology translation or integer cast should be applied before the
system/code filter.

The authoritative Delta had 56,535 total `MedicationAdministration`
resources: 36,131 hospital-profile resources and 20,404 ICU-profile
resources. The ICU inputevents stream therefore has 20,404 served resources
in the demo. The target system/code returned 28 coding rows for 28 distinct
resources. The code did not occur under another medication coding system.
Thus the target coding-per-resource ratio is **28 / 28 = 1.000**, and the
coding projection does not multiply the target rows.

## Canonical ViewDefinition support columns

### MedicationAdministration

Use the FHIR choice path for the dosage `rate[x]` and `dose[x]` elements, not
the encoded Parquet field name. The following view was materialized
successfully over the authoritative Delta:

```json
{
  "resource": "MedicationAdministration",
  "select": [
    {
      "column": [
        { "path": "getResourceKey()", "name": "medadmin_key" },
        { "path": "subject.getReferenceKey(Patient)", "name": "patient_key" },
        { "path": "context.getReferenceKey(Encounter)", "name": "encounter_key" },
        { "path": "(effective).ofType(dateTime)", "name": "effective_datetime" },
        { "path": "(effective).ofType(Period).start", "name": "effective_period_start" },
        { "path": "(effective).ofType(Period).end", "name": "effective_period_end" },
        { "path": "(dosage.rate).ofType(Quantity).value", "name": "rate_value" },
        { "path": "(dosage.rate).ofType(Quantity).unit", "name": "rate_unit" },
        { "path": "(dosage.dose).ofType(Quantity).value", "name": "amount_value" },
        { "path": "(dosage.dose).ofType(Quantity).unit", "name": "amount_unit" }
      ]
    },
    {
      "forEach": "medication.ofType(CodeableConcept).coding.where(system='http://mimic.mit.edu/fhir/mimic/CodeSystem/mimic-medication-icu' and code='221662')",
      "column": [
        { "path": "code", "name": "item_code" },
        { "path": "system", "name": "code_system" },
        { "path": "display", "name": "code_display" }
      ]
    }
  ]
}
```

`context` is the R4 `Encounter` reference field on this resource. The Delta
schema calls it `context`; do not author the join as
`encounter.getReferenceKey(Encounter)`. `subject.getReferenceKey(Patient)` is
populated but no Patient join is required by dopamine's six-column output.
Both reference keys and the resource key are UUID-like strings and are
support/join columns only.

Pathling materialized every alias in the view above as Spark `STRING`,
including the effective datetime choices and Quantity values. The raw encoded
Quantity values are `decimal(32,6)`. The implementer must cast numeric aliases
to the manifest's `FLOAT` outputs and datetime aliases directly to
`TIMESTAMP_NTZ` before any coalesce. Do not cast an offset-bearing FHIR value
to timezone-aware `TIMESTAMP`.

### ICU Encounter identifier join

Materialize the ICU Encounter stream separately:

```json
{
  "resource": "Encounter",
  "select": [
    {
      "column": [
        { "path": "getResourceKey()", "name": "encounter_key" },
        { "path": "identifier.where(system='http://mimic.mit.edu/fhir/mimic/identifier/encounter-icu').value", "name": "stay_id_str" }
      ]
    }
  ]
}
```

Join `MedicationAdministration.encounter_key` to
`Encounter.encounter_key`, keep the ICU identifier system, and emit
`CAST(stay_id_str AS INTEGER)` as the final `stay_id`. Never use
`getResourceKey()` as `stay_id`; it returns the Encounter UUID. The demo had
140 ICU Encounter resources with 140/140 non-null ICU identifier values. All
28 dopamine administrations had a context reference and resolved to an ICU
identifier (28/28).

## Source-column to FHIRPath mapping

Source table to resource: `mimiciv_icu.inputevents` → ICU
`MedicationAdministration`. Identifier support table to resource:
`mimiciv_icu.icustays` → ICU `Encounter`.

The `*_str` and `*_key` names are intentional. They preserve FHIR strings and
UUID joins until the final SQL casts. Final types below are the oracle-manifest
types, not the materialized ViewDefinition types.

| Source column / output | Canonical FHIR extraction (`{path, name}`) | FHIR type | Observed target population / final type |
|---|---|---|---|
| `itemid` (filter only) | `{ "path": "code", "name": "item_code" }` under the constrained medication coding `forEach`; paired with `{ "path": "system", "name": "code_system" }` | `Coding.code` / `Coding.system` strings | `221662` with ICU medication system, 28/28; not emitted |
| `stay_id` | MA `{ "path": "context.getReferenceKey(Encounter)", "name": "encounter_key" }` → ICU Encounter `{ "path": "identifier.where(system='http://mimic.mit.edu/fhir/mimic/identifier/encounter-icu').value", "name": "stay_id_str" }` | `Reference(Encounter)` UUID, then `Identifier.value` string | 28/28 resolved; final `CAST(stay_id_str AS INTEGER)` → `INTEGER` |
| `linkorderid` | **No FHIRPath; no `select.column` is emitted** | Not represented | DuckDB source 28/28 non-null; final candidate requires typed `CAST(NULL AS INTEGER)` → `INTEGER` |
| `rate` → `vaso_rate` | `{ "path": "(dosage.rate).ofType(Quantity).value", "name": "rate_value" }` | `Quantity.value` decimal | 28/28; materialized `STRING`, final `CAST(rate_value AS FLOAT)` → `FLOAT` |
| `amount` → `vaso_amount` | `{ "path": "(dosage.dose).ofType(Quantity).value", "name": "amount_value" }` | `Quantity.value` decimal | 28/28; materialized `STRING`, final `CAST(amount_value AS FLOAT)` → `FLOAT` |
| `starttime` | `{ "path": "(effective).ofType(Period).start", "name": "effective_period_start" }` | `effective[x]` choice, `Period.start` `dateTime` | 28/28 in target; materialized `STRING`, final `TRY_CAST(... AS TIMESTAMP_NTZ)` → `TIMESTAMP` |
| `endtime` | `{ "path": "(effective).ofType(Period).end", "name": "effective_period_end" }` plus `{ "path": "(effective).ofType(dateTime)", "name": "effective_datetime" }` | `effective[x]` choice, `dateTime` in either branch | target Period.end 28/28 and dateTime 0/28; final `COALESCE(TRY_CAST(effective_period_end AS TIMESTAMP_NTZ), TRY_CAST(effective_datetime AS TIMESTAMP_NTZ))` → `TIMESTAMP` |

The unit support paths are `{ "path": "(dosage.rate).ofType(Quantity).unit", "name": "rate_unit" }` and `{ "path": "(dosage.dose).ofType(Quantity).unit", "name": "amount_unit" }`. They are FHIR strings and were populated 28/28 as `mcg/kg/min` and `mg`, respectively. The source SQL does not select or filter `rateuom` or `amountuom`, so do not add unit predicates or conversions.

The immutable full manifest declares the comparison key `(stay_id, starttime)`
and six output columns with types `INTEGER, INTEGER, FLOAT, FLOAT, TIMESTAMP,
TIMESTAMP`; its full-oracle row count is 16,892. In the demo DuckDB source,
`inputevents WHERE itemid=221662` had 28 rows, 28/28 non-null for every

Joining the 28 Delta target rows to the DuckDB source on `stay_id,starttime`
gave 28/28 paired rows, with no source-only or FHIR-only rows. Exact checks

|---|---:|

| `endtime` from Period.end | 28/28 |

The numeric differences are not a wrong path or unit conversion. The served
Delta Quantity encoding is `decimal(32,6)`, while the source oracle columns are
`FLOAT`; the source values contain more precision than the served FHIR value.
The raw source-to-FHIR numeric comparison before the target `FLOAT` cast was
not bitwise exact for all 28 rows, but the six-decimal FHIR representation was
within `1e-6` for every target value. The full-precision source values cannot
be recovered from the served resource.

## Gaps and implementer obligations

* **`linkorderid` — not representable.** `MedicationAdministration.identifier`
  is absent on all 56,535 served MedicationAdministration resources. The ICU
  ETL creates the opaque resource UUID from `stay_id-orderid-itemid`, but does
  not write `linkorderid`, `orderid`, or an inputevent Identifier. The UUID
  cannot be inverted to the source `linkorderid`; do not use `getResourceKey()`
  as a numeric surrogate. Emit typed NULL `INTEGER`.
* **`starttime` for a rate-null inputevent — absent and not representable.**
  The ETL's dateTime branch stores only source `endtime`. There is no FHIR
  start element in that branch and no exact derivation of source `starttime`.
  The demo dopamine target has rate non-null on 28/28, so this gap is not
  exercised here; the general ICU choice probe confirms the dateTime branch
  exists.
* **Rate and amount full precision — not representable, but deterministically
  approximable.** The six-decimal Delta Quantity values gave 28/28 within
  `1e-6` of the DuckDB FLOAT values in the dopamine demo, but only 7/28 and
  22/28 bitwise equality after final FLOAT casting. Preserve the direct FHIR
  values; do not invent a rate/amount conversion. This is an upstream
  served-data precision loss, not an absent field.
* `stay_id`, `rate`, `amount`, `starttime`, and `endtime` have direct or exact
  join mappings for all 28 demo target rows. No approximation is used for
  those mappings.

## Repository notes and provisional fragments

The curated `MIMIC_NOTES.md` entries that changed a mapping decision were:

* **MIMIC IDs live in `identifier.value` as strings**: forced the ICU Encounter
  identifier join for `stay_id`, kept UUID reference keys join-only, and
  required the final integer cast.
* **Encounter has three identifier systems; class discriminates none**: forced
  the `encounter-icu` identifier system rather than Encounter class.
* **Polymorphic fields mix datatypes**: required both effective choice aliases
  and the end-time coalesce.
* **FHIR datetimes carry an offset**: required direct `TIMESTAMP_NTZ` casts.
* **Quantity.value ViewDefinition aliases materialize as VARCHAR**: required
  final numeric casts; the fresh probe additionally measured the raw
  `decimal(32,6)` precision.
* **Raw NDJSON is stale**: all resource and code claims came from Delta, not
  the gzipped NDJSON files.

The curated itemid/code-system rule also supplied the no-translation policy,
but its Observation-specific examples do not define this medication stream;
the `mimic-medication-icu` system was established directly from served Delta.
Medication-name display and prescription Medication notes were not relevant
to this ICU itemid-coded stream; the target display happened to be non-null
28/28.

All existing provisional `MIMIC_NOTES.d/` fragments were read:

`cardiac_marker.md`, `blood_differential.md`, `code_status.md`, and
