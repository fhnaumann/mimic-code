the exact system. The system-plus-code pair is the discriminator; do not use

        { "path": "(effective).ofType(Period).end", "name": "effective_period_end" },

      "forEach": "medication.ofType(CodeableConcept).coding.where(system='http://mimic.mit.edu/fhir/mimic/CodeSystem/mimic-medication-icu')",

The source SQL does not select or filter `rateuom` or `amountuom`, so the unit
paths are support-only and no unit conversion belongs in the port:

```text
(dosage.rate).ofType(Quantity).unit  -> rate_unit   (FHIR string)
(dosage.dose).ofType(Quantity).unit  -> amount_unit (FHIR string)
```

The source predicate `rate IS NOT NULL` must be represented by filtering the
selected code rows on the non-null FHIR rate value. The ICU ETL uses the same
rate state to write `effectivePeriod` versus `effectiveDateTime`, so a
rate-bearing source row has Period start/end. The general dateTime branch is
still projected so the choice is not silently dropped, but it has no source
starttime to recover if encountered.

## `orderid` representation and gap assessment

`orderid` is **not represented independently**. The raw served
MedicationAdministration schema has no `orderid` element. On the complete ICU
stream, `MedicationAdministration.identifier` was non-empty on 0/20,404,
`request` was populated on 0/20,404, and `request.identifier.value` was
populated on 0/20,404. The ETL writes no inputevent identifier: it uses
`orderid` only inside the opaque UUID expression at
`fhir_medication_administration_icu.sql:20`, then serializes the UUID as the
resource `id` at line 40. The resource id is identity only. Parsing,
regenerating, brute-forcing, hardcoding, or otherwise inverting it to recover
`orderid` is forbidden and is not a FHIR mapping.

This is a **not representable** gap, not an absent-but-derivable field. No
independent FHIR element carries the value, and no measured approximation is
available. A typed NULL is the honest shape-preserving candidate for the
`INTEGER` output, but it will not reproduce the oracle value.

The loss is potentially **essential** for this concept: `orderid` is an
ordinary output column and is the immutable full-oracle comparison key for
`neuroblock` (14,174 rows; key `orderid`). The source table's declared key is
`(orderid, itemid)`, while the filtered result's manifest key is empirically
`orderid`. Because the missing value can affect row identity, keyed alignment,
grouping, and downstream inputevent linkage, recommend whole-concept blocking
to the equivalence judge rather than presenting the remaining values as an
exact six-column port. This is evidence for the judge, not a terminal block or
acceptance by the prober.

Other gaps and transformations:

* `starttime` is not representable on the general rate-null `effectiveDateTime`
  branch because the ETL writes only source `endtime` there. The canonical
  neuroblock predicate excludes those rows (`rate IS NOT NULL`), so this branch
  should not affect the selected full-data rows if the FHIR code/rate filter is
  applied correctly.
* Full source FLOAT precision is not preserved by the served Quantity's
  `decimal(32,6)` encoding. Direct FHIR Quantity values are the faithful
  deterministic approximation; this local target has no rows on which to
  measure an agreement fraction. Do not use resource identity to recover more
  precision.
* FHIR datetime strings carry offsets. Cast the serialized values directly to
  `TIMESTAMP_NTZ`, not to timezone-aware `TIMESTAMP`; the upstream
  `TIMESTAMPTZ` cast can irreversibly normalize DST-gap wall times. No
  neuroblock target row is available in this demo to quantify that effect.

## Notes and provisional fragments read

Curated `MIMIC_NOTES.md` entries that changed this mapping decision were:

* **MIMIC ids live in `identifier.value` as strings** — forced `stay_id` through
  the ICU Encounter identifier and required a final integer cast; UUID resource
  and reference keys remain join-only.
* **Encounter has three identifier systems; class discriminates none** — forced
  the exact `encounter-icu` identifier system rather than `Encounter.class`.
* **Polymorphic fields mix datatypes across rows** — required both effective
  choice aliases and the Period.end/dateTime end-time coalesce.
* **FHIR datetimes carry an offset; cast to `TIMESTAMP_NTZ`** — determines the
  datetime conversion and prevents session-timezone shifts.
* **Quantity.value ViewDefinition aliases materialize as VARCHAR** — requires
  final numeric casts; the fresh schema probe additionally confirmed raw
  `decimal(32,6)` Quantity fields.
* **Raw NDJSON is stale; probe Delta** — all served counts and schema results
  above came from embedded Pathling over Delta.
* **Essential source loss blocks the whole derived concept** — makes the absent
  `orderid` a potentially concept-essential gap because it is the output and
  manifest key; the prober does not make the terminal decision.
