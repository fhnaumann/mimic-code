## Resource mapping and discriminator

`mimiciv_icu.inputevents` maps to the ICU
`MedicationAdministration` resource stream generated by
`/Users/nau025/Documents/mimic-fhir/sql/fhir_medication_administration_icu.sql`.
The ETL writes the input-event item ID as a medication CodeableConcept coding:

```text
system = http://mimic.mit.edu/fhir/mimic/CodeSystem/mimic-medication-icu
code   = "221653"
display = "Dobutamine"
```

The ViewDefinition should constrain the repeated coding inside the `forEach`,
then filter the exact string code in SQL.  Do not use `meta.profile` or the
display as the discriminator:

```json
{
  "forEach": "medication.ofType(CodeableConcept).coding.where(system='http://mimic.mit.edu/fhir/mimic/CodeSystem/mimic-medication-icu')",
  "column": [
    { "path": "code", "name": "item_code" },
    { "path": "system", "name": "code_system" },
    { "path": "display", "name": "code_display" }
  ]
}
```

The source literal `itemid = 221653` was confirmed in the Delta.  The exact
system/code combination returned 44 coding rows for 44 distinct resources;
the coding-per-resource ratio is therefore **1.000**.  There were no rows for
code `221653` under another medication coding system.  Across the complete ICU
medication coding stream, the ICU system had 20,404 coding rows for 20,404
resources (also 1.000), so the target `forEach` does not multiply rows.

## Canonical ViewDefinition support views

### MedicationAdministration

Use these flat columns.  The UUID columns are join/support columns and are not
MIMIC identifiers in the output.

```json
{
  "resource": "MedicationAdministration",
  "select": [
    {
      "column": [
        { "path": "getResourceKey()", "name": "medadmin_key" },
        { "path": "subject.getReferenceKey(Patient)", "name": "patient_key" },
        { "path": "context.getReferenceKey(Encounter)", "name": "encounter_key" },
        { "path": "(effective).ofType(dateTime)", "name": "effective_datetime" },
        { "path": "(effective).ofType(Period).start", "name": "effective_period_start" },
        { "path": "(effective).ofType(Period).end", "name": "effective_period_end" },
        { "path": "(dosage.dose).ofType(Quantity).value", "name": "amount_value" },
        { "path": "(dosage.rate).ofType(Quantity).value", "name": "rate_value" },
        { "path": "(dosage.dose).ofType(Quantity).unit", "name": "amount_unit" },
        { "path": "(dosage.rate).ofType(Quantity).unit", "name": "rate_unit" }
      ]
    },
    {
      "forEach": "medication.ofType(CodeableConcept).coding.where(system='http://mimic.mit.edu/fhir/mimic/CodeSystem/mimic-medication-icu')",
      "column": [
        { "path": "code", "name": "item_code" },
        { "path": "system", "name": "code_system" },
        { "path": "display", "name": "code_display" }
      ]
    }
  ]
}
```

Pathling 9.6.0 materializes all of the above ViewDefinition aliases as
string-like Spark `STRING` columns, including Quantity values and datetime
choices.  The underlying encoded Quantity fields are Spark
`decimal(32,6)`, and the FHIR types are decimal/dateTime respectively.  Cast
the numeric aliases to the manifest's `FLOAT` in the final SQL.  Cast the
datetime strings directly to `TIMESTAMP_NTZ`; do not use an offset-aware
`TIMESTAMP` cast.

### ICU Encounter identifier join

The `MedicationAdministration.context` field is the FHIR R4 `Encounter`
reference (the served schema calls it `context`, not `encounter`).  Materialize
the ICU Encounter stream separately:

```json
{
  "resource": "Encounter",
  "select": [
    {
      "column": [
        { "path": "getResourceKey()", "name": "encounter_key" }
      ]
    },
    {
      "forEach": "identifier.where(system='http://mimic.mit.edu/fhir/mimic/identifier/encounter-icu')",
      "column": [
        { "path": "system", "name": "stay_system" },
        { "path": "value", "name": "stay_id_str" }
      ]
    }
  ]
}
```

Join `MedicationAdministration.encounter_key` to
`Encounter.encounter_key`, and emit `CAST(stay_id_str AS INTEGER)` as
`stay_id`.  The UUID reference key is only a join key.  The Delta had 140 ICU
Encounter identifier rows for 140 distinct Encounters, and all 44 targeted
MedicationAdministrations had a non-null context reference, joined to an ICU
identifier, and a non-null stay identifier (44/44).  A left join is safest for
row preservation; this target has no join loss.

No Patient join is required by the six-column source output.  The subject
reference was nevertheless populated for all 44 target rows (44/44).

## Source column → FHIRPath mapping

The final output types are the types in the full oracle manifest.  The
`*_str`/`*_key` names below are intentional: FHIR strings and UUIDs must remain
support columns until the final SQL casts.

| Source column / output | Canonical `{path, name}` | FHIR type | Observed target population / final type |
|---|---|---|---|
| `itemid` (filter only) | `{ "path": "code", "name": "item_code" }` inside the constrained medication coding `forEach`; system is `{ "path": "system", "name": "code_system" }` | `Coding.code` / `Coding.system`, string | `221653` under `mimic-medication-icu`, 44/44; not emitted |
| `stay_id` | MA support `{ "path": "context.getReferenceKey(Encounter)", "name": "encounter_key" }` → ICU Encounter `{ "path": "identifier.where(system='http://mimic.mit.edu/fhir/mimic/identifier/encounter-icu').value", "name": "stay_id_str" }` | Reference UUID, then `Identifier.value` string | 44/44 through the join; final `CAST(stay_id_str AS INTEGER)` → `INTEGER` |
| `linkorderid` | **No FHIRPath**; `MedicationAdministration.identifier` is absent and the ICU ETL does not write `linkorderid` | Not represented | Source demo 44/44 non-null; candidate must emit typed `CAST(NULL AS INTEGER)` and declare the gap |
| `rate` → `vaso_rate` | `{ "path": "(dosage.rate).ofType(Quantity).value", "name": "rate_value" }` | `Quantity.value` decimal | 44/44; ViewDefinition alias `STRING`, final `CAST(rate_value AS FLOAT)` → `FLOAT` |
| `amount` → `vaso_amount` | `{ "path": "(dosage.dose).ofType(Quantity).value", "name": "amount_value" }` | `Quantity.value` decimal | 44/44; ViewDefinition alias `STRING`, final `CAST(amount_value AS FLOAT)` → `FLOAT` |
| `starttime` | `{ "path": "(effective).ofType(Period).start", "name": "effective_period_start" }` | `effective[x]` choice, `Period.start` dateTime | 44/44 in this target; alias `STRING`, final `TRY_CAST(... AS TIMESTAMP_NTZ)` → manifest `TIMESTAMP` |
| `endtime` | `{ "path": "(effective).ofType(Period).end", "name": "effective_period_end" }` **and** `{ "path": "(effective).ofType(dateTime)", "name": "effective_datetime" }` | `effective[x]` choice, dateTime in either branch | 44/44 via Period.end and 0/44 via dateTime; final `COALESCE(TRY_CAST(effective_period_end AS TIMESTAMP_NTZ), TRY_CAST(effective_datetime AS TIMESTAMP_NTZ))` → manifest `TIMESTAMP` |

The unit support paths are `(dosage.dose).ofType(Quantity).unit` and
`(dosage.rate).ofType(Quantity).unit`, both string-like and populated 44/44 in
the target.  The source SQL neither selects nor filters `amountuom` or
`rateuom`, so no unit predicate or conversion belongs in the port.

The raw Delta schema also exposes the same choice values as
`effectiveDateTime`, `effectivePeriod.start/end`, `dosage.dose.value`, and
`dosage.rateQuantity.value`; the canonical FHIRPath choice expressions above
are the authorable paths and were materialized successfully.  The dose/rate
choice is Quantity, not `value.ofType(Quantity)` on an Observation.

## Natural key and oracle check

The immutable full manifest declares the natural/comparison key
`(stay_id, starttime)`, 8,513 full-oracle rows, with output types
`INTEGER, INTEGER, FLOAT, FLOAT, TIMESTAMP, TIMESTAMP`.  This is an empirical
comparison key, not the FHIR resource key and not `linkorderid`.  Do not use
`getResourceKey()` as `stay_id`, and do not key on `linkorderid`.

On the demo DuckDB oracle, `inputevents WHERE itemid=221653` had 44 rows,
44/44 non-null for `stay_id`, `linkorderid`, `rate`, `amount`, `starttime`, and
`endtime`, and 44 distinct `(stay_id,starttime)` keys.  The Delta candidate
had 44 rows; the natural-key join was 44/44 on both sides with zero
oracle-only or candidate-only rows.  Agreement was:

| Output | Oracle/FHIR agreement |
|---|---:|
| `stay_id` | 44/44 exact |
| `starttime` | 44/44 exact |
| `endtime` | 44/44 exact |
| `vaso_rate` | 16/44 binary-exact after `FLOAT` cast; 44/44 within `1e-6` |
| `vaso_amount` | 36/44 binary-exact after `FLOAT` cast; 42/44 within `1e-6`, max absolute difference `1.5258789e-05` |
| `linkorderid` | no FHIR value/path; source 44/44 non-null |

The small numeric differences are an upstream representation effect, not a
different mapping: the served Quantity value is encoded/materialized as
`decimal(32,6)` and the manifest requires a `FLOAT`, while the oracle source
column is a floating value.  The direct Quantity paths are still the only
faithful mapping; no unit conversion or heuristic should be introduced.

## Gaps

* **`linkorderid`: not representable.** The ICU ETL creates the resource UUID
  from `stay_id-orderid-itemid` but does not write `linkorderid`, `orderid`, or
  an inputevent identifier.  The target probe found identifiers on 0/44
  dobutamine resources and 0/20,404 ICU inputevent MedicationAdministrations.
  The UUID is opaque and cannot be inverted to `linkorderid`.  Emit a typed
  NULL `INTEGER`, not an estimate.
* **`starttime` on a rate-null inputevent: absent and not representable.** The
  ETL writes only `effectiveDateTime = endtime` in that branch.  This did not
  occur in the demo dobutamine target (rate non-null 44/44), where Period.start
  reproduces all starts exactly.  For a full-data row using the dateTime branch,
  there is no FHIR element or exact derivation for the original start.
* There is no absent-but-derivable or safely approximable output column in the
  observed dobutamine target.  Numeric Quantity precision is present-but-
  transformed as measured above; it should not be replaced with an estimate.

## Repository notes used

The curated notes that changed this mapping decision were:

* **“MIMIC ids live in `identifier.value` as STRINGs — `getResourceKey()` is a
  UUID”**: made `stay_id` come from the ICU Encounter identifier and kept
  `context.getReferenceKey(Encounter)` as a UUID-only join column, with a final
  integer cast.
* **“Polymorphic fields mix datatypes across rows — COALESCE them”**: required
  both effective choice variants and the end-time coalesce.
* **“FHIR datetimes carry an offset — cast to `TIMESTAMP_NTZ`, never to
  `TIMESTAMP`”**: determines the final datetime cast.
* The raw-Delta-only rule was followed; no ndjson or live server data was used.
